# 916 Dent & Detail — project decisions & assumptions
| ID | Decision / assumption | Why |
|---|---|---|
| P-001 | Project lives in `916-dent-detail/` inside the org repo (branch `claude/916-dent-detail-build`). | Repo is the only persistent store; containers are ephemeral. |
| P-002 | Source video has an AAC audio stream and an embedded MJPEG cover stream; both stripped. 241 frames @24fps → ~120 frames means every 2nd frame. | Verified with ffprobe. |
| P-003 | No hero-video-wide.mp4 supplied → desktop uses the vertical scrub in a tall rounded panel (55% width) over blurred hero-beading.png. | Spec fallback. |
| P-004 | Everything external (Supabase, Stripe, Twilio, Resend, Anthropic, GA4, Meta) has a mock/no-key mode. | Hard gate: no accounts/spend by agents; app must run with zero keys. |
| P-005 | Next.js 16.4.1 (`npm view next version` on 2026-10-15), React 19.3.1, Turbopack build. TypeScript pinned `~5.9` and ESLint 9: TS 7.0.2 is "latest" but typescript-eslint 8 peers `typescript >=4.8.4 <6.1.0`. | Lint must run clean; TS 7 would break the lint toolchain. |
| P-006 | Tailwind v4, tokens in CSS-first `@theme` (`src/app/globals.css`), no `tailwind.config.js`. Builder agent rule "never add Tailwind" is for `blueprint/` client sites; this SPEC and D-029 require Tailwind. | v4 has no JS config by default; `@theme` generates `bg-onyx`, `text-gold` and the rest. |
| P-007 | Hero pin = CSS `position: sticky` stage inside a 350svh track (100svh stage + 250svh scrub), not a GSAP pin. ScrollTrigger only maps progress. An inline head script picks scrub vs static before first paint. | No pin-spacer insertion means no layout shift (CLS 0 measured). |
| P-008 | Static state (reduced motion / ≤2 cores / ≤2 GB / Save-Data) = LAST frame (fully beaded, clean) + all copy fading in. Reduced motion is served by `<picture media="(prefers-reduced-motion: reduce)">` (no JS); low-end swaps in via JS. Scrub mode starts on frame 0 (dent visible). | Showing the dented frame next to "Dents gone." contradicts the copy; the last frame is the result. |
| P-009 | 121 frames (every 2nd of 241, includes the last). Mobile 720x1280 q80; desktop = 720x1000 crop (top 140 px) of the same 720w source, q80, no upscaling. | No wide video exists. Upscaling adds bytes, not detail. The desktop panel is roughly square, so the crop drops pixels that are never shown. |
| P-010 | Loading: poster `<img>` immediately (fetchpriority high); first 10 frames 2.5 s after `load` or on first intent; GSAP/ScrollTrigger/Lenis and the other 111 frames on first scroll/touch/key/pointer, nearest-to-current first, then coarse-to-fine (every 8th, 4th, 2nd, rest), 4 at a time. | Lighthouse TBT dropped from 1,130 ms to 90-250 ms once motion JS was moved off the load path. |
| P-011 | Header logo = transparent D-mark (`d-mark-80.webp`) + "916 DENT & DETAIL" as live Michroma text. The full lockup stays for OG/footer use. | The full lockup at 40 px tall makes the wordmark about 6 px high, which is illegible. |
| P-012 | Eco section copy kept general ("low-water methods", "runoff captured", "the way Sacramento-area stormwater rules intend"); no equipment, permit or volume claims. `[OWNER: confirm reclaim equipment & permits]` in TODO.md. | SPEC asks for the section; specifics are unverified. |
| P-013 | Reviews = 3 dashed cards visibly marked `[OWNER] real review n` and "Placeholder, not a customer review". No stars, no counts, no aggregateRating in JSON-LD. | SPEC + hard rule: no invented reviews/ratings. |
| P-014 | Phone placeholder (916) 555-0100 (fictional 555-01xx range), email hello@example.com; visible `[OWNER]` markers in UI and both omitted from JSON-LD while `placeholder: true`. `npm run check:owner` exits 1 until every placeholder is gone. | tel:/sms: links need a value; a reserved fictional number cannot reach a stranger. |
| P-015 | Fonts: woff2 from @fontsource/michroma@5.3.0 + @fontsource/inter@5.3.0 (400, 600), subset to Basic Latin + Latin-1 + common punctuation by `scripts/subset-fonts.sh` (66 KB → 40 KB). `font-display: swap` kept. | Bytes before first paint drive simulated mobile LCP. |
| P-016 | Posters AVIF q36 (mobile 22 KB) instead of q50 (40 KB); visually compared, dent still crisp. Frames stay q80 per SPEC. | LCP budget. |
| P-017 | No runtime image optimizer (`images.unoptimized`): every image is pre-sized by the pipeline; plain `<img>`/`<picture>` with explicit width/height. | Predictable bytes; no sharp at runtime on the server. |
| P-018 | Membership tiers named Maintain / Protect / Showroom with proposed contents; featured tier labelled "Recommended" (not "Most popular"). | "Most popular" would be an unsupported claim. |
| P-019 | /book is a real "text us a photo" page (sms:/tel: CTAs) until the Phase 2 engine. No "coming soon" copy shown to customers. | SPEC: nav must not 404; shells must point at the right CTA. |
| P-020 | Section motion = one GSAP timeline per section keyed by `data-motion` (steps, grid, reveal, parallax, draw, pins, tiers, slide, fade). Nothing is hidden before JS; no motion in static mode. | Restrained, and content still works without JS. |
| P-021 | Service-area map is a schematic inline SVG (approximate relative positions, labelled "not to scale") plus a real `<ul>` of the 14 cities. | No external map script; the list is the accessible source. |
| P-022 | Named org agents (builder/qa/scout/…) became unavailable after Phase 1; Phases 2+ run as general-purpose agents with the same briefs/gates. Phases 2 (booking), 6 (SEO) and 7 (marketing md) run in parallel on disjoint paths. | Tool availability changed mid-session; parallelism saves wall-clock. |
| P-023 | Phase 1 LCP misses by 0.1s on Lighthouse mobile (median 2.6s vs 2.5s target); real paint is ~0.2s. Accepted for now, remeasure on Vercel host at launch. | Builder handoff T-916-P1; threshold not changed. |
| P6-001 | Blog = `next-mdx-remote@6` (`/rsc`) reading `content/blog/*.mdx` with a tiny built-in frontmatter parser; no @next/mdx. | Works with Next 16 App Router RSC, no webpack-only options, posts stay plain files. |
| P6-002 | Service/city copy = typed TS data (`src/content/seo/**`) rendered by shared templates; files import only `import type` + relative `.ts` paths so Node type-stripping can load them in scripts. Added `allowImportingTsExtensions` to tsconfig. | One content source for pages, schema, sitemap, similarity gate and redirects. |
| P6-003 | Clean URLs: /services/<slug>, /areas/<city>, /blog/<slug>, /blog/tag/<tag>, /blog/rss.xml. /services stays the hub (rewritten, 9 spokes); /areas is the city hub. Home grid + footer now point at spokes. | Hub-and-spoke. |
| P6-004 | `scripts/check-similarity.mjs` runs as `prebuild`: 5-word-shingle Jaccard on every pair, fail >35%; word minimums (services 900, cities 600, posts 700); description <=155; unique titles. Measured max overlap: services 0.50%, cities 2.43%, posts 0.77%. | Doorway-page defence; build fails instead of shipping clones. |
| P6-005 | City pages get structure differences from their own `sections` plus `extra.ts`; travel block moves above the jobs list for `far` cities. Drive-time is qualitative; fee numbers appear only when `PRICES_ARE_PLACEHOLDERS` is false (src/lib/seo/travel.ts). | No invented drive times or fees. |
| P6-006 | Service prices render only from `serviceFromPrice`; null => "priced from your photos" + link to /pricing (no [OWNER] marker on public SEO pages). Service JSON-LD omits `offers` unless a real number exists. Phase 2 placeholder fixedPrices are never read. | Spec: no hardcoded prices; no fake offers. |
| P6-007 | Schema: sitewide @graph = Organization (+sameAs from config, empties skipped) + AutoRepair/LocalBusiness (areaServed only, no address, phone/email only when not placeholder) + WebSite. No aggregateRating/review anywhere; `check:seo` fails the build gate if one appears. Old `BusinessJsonLd` now delegates to `lib/seo/schema.ts`. | Single source; SPEC hard rules. |
| P6-008 | Dynamic OG/Twitter images via `next/og` per service, city, post (branded text card, no photos or claims). `images.formats` = AVIF, WebP kept but runtime optimizer stays off (P-017). | No images to optimise yet; pipeline already emits AVIF/WebP. |
| P6-009 | Thin blog tags (<2 posts) are `noindex,follow` and excluded from sitemap; `/booking/` and `/api/`, `/admin/` disallowed in robots. | Avoid thin pages; tokenized links. |
| P6-010 | `track()` fan-out is consent-gated: GA4 + Vercel custom events need "analytics"; Meta Pixel + Google Ads need "marketing"; nothing loads before choice (opt-in), GPC forces marketing off, banner only renders when a tracker ID exists, appears after 1.5 s idle. Vercel Analytics component only on Vercel (`VERCEL=1`) or `NEXT_PUBLIC_VERCEL_ANALYTICS=1`. | CA-friendly, Lighthouse-safe, zero-key demo stays clean. |
| P6-011 | call/text tracking moved from per-link onClick to one delegated listener (`data-track-where` on CallLink/TextLink; any raw tel:/sms: link also tracked). | Spec; avoids double fire. |
| P6-012 | Attribution: extended Phase 2's `src/lib/attribution.ts` (kept its API), added `getAttribution()` and `metaIdentifiers()`; `AnalyticsRoot` calls `captureAttribution()` on every landing so UTMs/gclid/fbclid survive navigation to /book. | Landing page is rarely /book. |
| P6-013 | CAPI helper is server-only, needs explicit `marketingConsent`, hashes per Meta rules, `event_id` shared with the browser event, mock-logs without keys. No API route was added (src/app/api is Phase 2's lane). | Dedupe without crossing lanes. |
| P6-014 | `NEXT_DIST_DIR` honored in next.config.ts and `.next-*` ignored by git and eslint so parallel agents can build without clobbering `.next`. | Parallel agents shared one tree. |
| P6-015 | Meta description for / and /services shortened to <=155 (layout metadata no longer uses `site.description`). | check:seo limit. |

| P-025 | Phase 6 accepted. Follow-ups: Phase 2 must call sendCapiEvent (event_id from track() + consent); privacy/terms page needed (add in Phase 8); redirects map reserves /contact,/estimate,/about; Lighthouse dips <90 happened under CPU load, re-measure on idle machine in Phase 8. | T-916-P6 handoff |
| P2-001 | Mock mode is per service and automatic: Supabase (in-memory seeded store, optional `MOCK_DB_FILE`), Stripe (fake `pi_mock_*` intent + DEMO confirm button), Twilio/Resend (logged + in-memory outbox), Anthropic (deterministic rule-based quote, labelled DEMO), Google Calendar (no-op). Real clients activate when their keys exist. | Hard rule: runs with zero keys. |
| P2-002 | One typed `Repo` (`src/lib/db`) with generic tables (snake_case rows = SQL columns) plus three special methods: overlap-checked booking create/move, idempotent queue enqueue, atomic queue claim. Phases 3-5 call `repo()` only. | Same code path in mock and Supabase; double-booking is also enforced by a Postgres exclusion constraint. |
| P2-003 | Prices are placeholder numbers in `config/pricing.ts` with `PRICES_ARE_PLACEHOLDERS = true`; UI shows an [OWNER] marker while true. Dents never get a fixed price without photo quote. Detailing "high" = price x (1 + `detailSpread`). | Spec: no hardcoded prices; demo must work. |
| P2-004 | Quote model call uses `output_config.format` JSON schema, no forced tool_choice (400s on Sonnet 5.5), effort `low`. The server validates with zod, clamps to config bounds (floor = minimum, ceiling from panel count x top per-panel rate x 1.25), sanitizes notes (no links/emails/phones), and falls back to "needs review" (no price) on refusal, bad JSON or errors. No server-side `fallbacks` beta was enabled. | Injection resistance: the model only reports damage; the business rules price it. |
| P2-005 | Availability is a pure function over (techs, weekly hours, blackouts, admin blocks, bookings, weather flags). Day stepping uses local dates; durations are real elapsed ms; nonexistent DST wall times are skipped; repeated times use the earlier. Gap between jobs = buffer + drive minutes from ZIP distance x 1.3 / 28 mph. | DST-safe and testable. |
| P2-006 | Slot hold: booking is created `pending_deposit` with a 15 min hold that blocks the calendar; the cron expires lapsed holds; a late payment on an expired hold is refunded rather than double-booked. Changing details after reserving releases the old hold first. | Prevents ghost reservations and self-blocking. |
| P2-007 | Deposit policy (config): cancel >=48h refund, 24-48h credit (90 days), <24h kept; reschedule free >=24h, allowed to 4h with deposit carried over, closed inside 4h, max 2. Text shown to customers is generated from the same config. | Placeholder windows for owner to confirm. |
| P2-008 | Customer links are HMAC-SHA256 signed tokens (booking id + expiry), verified in the API; no customer-facing table access under RLS. Mock mode uses a fixed dev secret; setting Supabase keys without `BOOKING_TOKEN_SECRET` throws. | Customers have no accounts. |
| P2-009 | Notifications: DB queue with unique `dedupe_key` (idempotent), atomic claim, 3 attempts. SMS needs recorded opt-in (exact wording stored) and no STOP; quiet hours 9pm-8am local defer SMS (email still goes) except confirmation, on-the-way, cancellation; a 2h reminder that could only text after the appointment is skipped. Reminders include the start time in their key so a reschedule creates new ones and cancels old ones. | TCPA hygiene; reschedule safety. |
| P2-010 | SMS consent checkbox is never pre-checked, never persisted in the draft, optional (email-only booking works). | TCPA: consent must be fresh and not a condition of purchase. |
| P2-011 | `/api/photos` (one image per request, magic-byte check, 3 MB) and `/api/lead` (unbookable-ZIP capture) were added beyond the listed routes; `/booking/[token]` page lives outside `src/app/book/`. | Needed by steps 3, 4 and the manage page. |
| P2-012 | `vercel.json` cron every 5 minutes for `/api/cron/dispatch`. Vercel Hobby only allows daily crons. | Reminders need minute-level resolution. |
| P2-013 | Booking CAPI: client sends its `event_id` and consent after confirmation; server calls `sendCapiEvent` once per booking and only with marketing consent. | Closes P-025 follow-up. |

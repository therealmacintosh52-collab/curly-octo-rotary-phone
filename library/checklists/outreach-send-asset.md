# Checklist: outreach send asset (owner-sent text/DM kits)
Owner: qa · Created 2026-10-12 from T-008 (six files, 2 rounds). Updated T-015 (2026-10-13). Re-verify wording rules after 2026-11-12.

1. IDs and money: price, deposit, threshold, test ID (EXP-A#) and approval ID (A-###) equal EXPERIMENTS.md and the DECISIONS.md mapping (D-020: A-007=EXP-A2, A-008=EXP-A3, A-009=EXP-A4). Scope (recipient type) equals the card; no extra trades. Reserve assets name "needs new approval ID".
2. Manual send line in COMPLIANCE: "own phone, by hand, one text each, no bulk app, no auto-dialer, no group text, no scheduled sends"; silence/"no/stop" = never contact again.
3. Opt-out: every message the owner sends to someone who has not agreed (and every reply-only follow-up) ends with a STOP line. Inbound-only assets: mark N/A.
4. Length: script-count every fenced single-line message (raw, and after fills: name 12, business 25, one-true-thing 60, link 30, refund term 60). Cold openings and variants under 320 after fills (one SMS-plus segment budget). Replies over 320 are advisory unless the file calls them "text"; terms go as two messages or a linked page.
5. Claims: grep for guarantee, testimonial, income, "limited", "today only", "if you were happy", REPLACE-ME. Every named business/rule is tagged VERIFIED (url, date, quote) or UNVERIFIED. Portfolio = "sample builds" until a paid client agrees.
6. Review-card wording: ask every customer, no reward, no selecting, no private-feedback detour.
7. Legal/tax reads (CDTFA, TCPA, DNC, payment-app TOS): tagged "verify with a professional"; qa never rules on them.
8. Read each message aloud as the recipient: the opt-out line must not contradict the call to action (e.g. "Want details? Reply STOP" is ambiguous; give a separate YES/reply cue).
9. Line refs: cite file:line from a fresh `cat -n`, not from memory (T-008 qa cited a nonexistent l.61 in a 35-line file).
10. (added T-014) Live-call and walk-in scripts: count words by script (fills: name 3 words, observed fact 12 and 20 words) at 150 words/min; opener must be under 45 s with the 20-word fill. Texts after a spoken yes: script-count raw and at fills (name 25, first 10, business 25) and at the stress fill (first 12, name 40, business 40; the org's stress definition, also used in the call kit); all under 320, STOP line last. Worksheet row count by script.
11. (added T-014) Channel scan across SIBLING files: grep every call/audit script for "text it", "DM", "text version", "send as text" and check each against the first-touch rule (D-027/C3: walk-in or live call only; text only when the business asked). Section HEADERS count too: a header that says "send as text" with no gate is a send instruction (T-015 found audit l.46 this way). A rule fixed in one file is re-checked in every file that quotes the pitch (FP-10).
12. (added T-014) Sender identity scan: grep for the bracketed "[AGENCY NAME]" (must be 0 hits in library/) and for "Growth" or brand words in every sibling file; sender is the owner's legal name until the name decision is approved. A bare "AGENCY NAME" inside a checklist's own grep instruction is not a placeholder.
13. (added T-015) Named-line verification: for each line a re-check names, run `grep -nF` of the replacement string and confirm the hit is on the cited line number (not merely "present somewhere"). Line counts of multi-line lists (e.g. "19 lines") are counted by script, with the MOS order compared name by name.
14. (added T-015) Stress-fill counting: report three numbers per text: raw, kit stress (as item 10), and all-placeholders-40 as an advisory. A kit-stress pass with an all-40 overflow is PASS plus advisory, with a paste-ready shorter wording.
15. (added T-015) Send-instruction scan in owner action lists (TODAY.md and quests): any imperative "send / text / DM / call" for outreach is FAIL unless it sits behind an approval ID that is NOT on hold AND a logged spoken yes. A reply in the chat ("reply A-015 yes") is not an outreach send.
16. (added T-015) Dollar-tag scan: every "$" figure on a line carries a tag (VERIFIED, UNVERIFIED, ASSUMPTION, Expected) or a source on the same line (DECISIONS/STATE row, handoff line). A derived figure inherits its block's tag only if the block heading carries it; otherwise it is an advisory.
